# Golden test strategy

The first AMIX regression is the successful CFS **10-minute** multicam sample: the diarized overlap cut of CFS03 in the 49–59 minute window (legacy artifacts and the offline 16:9 plan/render path). It is a migration proof, not a demo reel.

The full Edited.mp4 program is a later fixture. It is long, and its protected regions are hand-authored. It is not the first golden.

## What must not drift

When the same inputs and pinned config are used:

- word timing
- speaker assignment
- turn boundaries
- overlap regions
- shot-plan decisions

Rendering bitstreams are not golden. Encoder drift is expected.

## No video in Git

Do not commit `03.mp4`, Edited.mp4, WAVs, or rendered MP4s.

Commit:

- A fixture manifest: source filename, time window, **content hash** of the source (and of the extracted window if the algorithm sees a cut file), algorithm versions, config snapshot.
- Expected JSON under `amix/tests/golden/cfs03_49_59/` (when tests exist). Until the engine exists, the expected files may be generated by a one-off export from legacy outputs and then reviewed. This document does not add those binaries or those JSON dumps yet if they are large; the **contract** is defined here so Phase 2 can add small JSON only.

If the hash does not match a local file, perception tests skip. Decision tests do not need the video.

## Two layers

### Exact (decision)

Inputs are committed JSON that was produced once from the sample (words with microsecond times, assignments, turns, overlap regions, layout rectangles, protected list — empty for this window if the 10-minute sample had none).

Assertions, byte-for-value after canonical JSON sorting:

- Each word: id, `start_us`, `end_us`, `raw_text`
- Each assignment: word id, participant id or `unknown`
- Each turn: id, participant, `start_us`, `end_us`, word ids
- Shot plan: contiguous half-open coverage of the window, presentation, participant id, reason, floor participant

Participant ids in the fixture are the imported mapping of legacy `speaker_a/b/c` for this file. The test fails if the planner emits `FULL_A`.

This layer runs in CI without media and without a GPU.

### Tolerance (perception)

Runs diarization and overlap against a local media file whose hash matches the manifest.

| Output | Assertion |
|---|---|
| Word times from a fresh Whisper run | Not in the default CI golden. ASR is sensitive to build and CPU. Pinning faster-whisper output is a manual, version-locked check. The exact layer uses the already accepted word JSON. |
| Diarization segments | Boundary tolerance of one clustering hop, or skip until the ported algorithm is bit-stable. Do not fail CI on a 40 ms boundary wobble. |
| Overlap regions | Start/end within one detector step (legacy step 0.25 s) and the same participant set. Region count must match. |
| Lip scores / YuNet dumps | Not asserted. |
| FFmpeg video | Not byte-compared. Optional: duration within 1 frame, audio stream copy flag, shot count. |

A perception failure does not rewrite the decision fixture. Someone updates the expected JSON only after a reviewed algorithm change, and that change bumps `algorithm_version`.

## Import bridge

Legacy files store float seconds and `speaker_a`. The golden import:

1. Converts times with the rule in [TIMELINE_MODEL.md](TIMELINE_MODEL.md).
2. Maps speakers through a fixture table to `ParticipantId`.
3. Maps `FULL_*` / `ORIGINAL_WIDE` / `PROTECTED_MASTER` into `presentation` + `participant_id`.

The expected shot JSON is the **AMIX** shape, so the test guards the new planner, not a string compare against `Edited_multicam_v1_plan.json` or the 49–59 plan filenames.

## Layout

Suggested tree when implemented (not created in this task):

```
amix/tests/golden/cfs03_49_59/
  manifest.json
  config.json
  participants.json
  layout.json
  expected/words.json
  expected/assignments.json
  expected/turns.json
  expected/overlaps.json
  expected/shots.json
```

`manifest.json` records where a developer may place the media locally. The path is not a repo path.

## Pass rule for migration

Phase 2 is not allowed to call the multicam port “behavior preserved” until the exact layer passes. The tolerance layer is required before replacing the legacy overlap detector, and optional before that if the port calls the same code through a thin adapter.
